Part 1：计算机网络体系结构

协议、接口、服务

  • 协议（Protocal）
    : 对等层（peer-to-peer layer）之间通信的规则，是水平的（horizontal）
  • 接口（Interface）
    ：同一系统内相邻层之间交换信息的连接点，是垂直的（vertical）
  • 服务（Service）
    ：下层为上层提供的功能支持，上层只关心服务，不关心实现细节

这时候可能有人要问了，水平？垂直？这是什么意思，我该怎么去理解这两个定义？

打个比方你就能记住了。

协议是「水平的」——想象两个国家的外交官，美国外交官只跟中国外交官说话，他们之间有一套共同的外交礼仪和规则，这就是协议。美国的外交官不会直接跑去跟中国的商务部官员谈外交事务，同样，中国的快递员也不会直接跟美国的CEO谈物流。

所以协议是对等层之间的约定：第 N 层只管跟对方的第 N 层沟通，中间隔了多少底层细节它不管。

接口是「垂直的」——同一台设备内部，上层像”老板”，下层像”员工”。老板把任务通过一个固定的方式交给员工（接口），员工做完后把结果返回。老板只关心”你能不能干这个活”，不关心你具体怎么干的。

所以接口是同一系统内上下层之间的连接点：上层通过接口调用下层服务，下层通过接口向上层提供服务。

分层结构（Layered Architecture）

  • 分层的目的：每层只管自己的事，上层不需要知道下层的实现细节
  • 每一层把数据封装（encapsulate）后传给下一层

ISO/OSIRM = ISO制定的OSI参考模型，也就是平时大家简称的OSI七层模型

  • 什么是TCP/IP模型

TCP/IP模型就是实际构建了Internet的协议体系结构
那么TCP/IP模型具体是怎么实现的呢?

      TCP/IP模型分成四个部分，从下往上依次为网络接口层（Network Interface Layer）,网际层（Internet Layer），传输层（Transport Layer），应用层（Application Layer）

时延、丢包与吞吐量

时延的四个组成部分

Total Delay    = Transmission Delay（发送时延）
               + Propagation Delay（传播时延）
               + Processing Delay（处理时延）
               + Queuing Delay（排队时延）
  • 发送时延（Transmission Delay）
    :数据从起点完全进入链路所需的时间
    • 数据长度单位：bits
    • 带宽单位：bps
    • 结果单位：seconds

公式

 
Transmission Delay = Data Length（数据长度） / Bandwidth（带宽）

注
1 byte = 8 bits，先把 bytes 转成 bits 再算！
bps在转换时为$10^{3}$作为一次进位

  • 传播时延（Propagation Delay）
    :信号在传输介质上从一端跑到另一端所需的时间
    • 信道长度单位：meters（米）
    • 结果单位：seconds

公式

 
Propagation Delay = Channel Length（信道长度） / Propagation Speed（传播速度）
  • 处理时延（Processing Delay）
    :路由器或交换机检查数据包头部、决定转发路径等处理花费的时间
    • 通常非常小（微秒级）
    • 在大多数考题中忽略不计
    • 但如果题目明确给了数值，记得加上
  • 排队时延（Queuing Delay）
    :数据包在路由器/交换机的队列中等待被处理的时间
    • 不确定值，取决于网络拥塞程度
    • 流量大 → 排队时间长 → 排队时延大
    • 流量小 → 排队时间短 → 排队时延趋于 0（或忽略不计）
    • 大多数考题中如果没特别说明，默认忽略

发送时延 vs 传播时延：核心区别

Transmission Delay（发送时延） Propagation Delay（传播时延）
取决于 数据长度 & 带宽 信道长度 & 传播速度
谁有关 发送方 链路本身
公式 $\frac{Data}{Bandwidth}$ Distance / Speed

RTT（Round-Trip Time，往返时延）

  • RTT
    :从发送方发出数据到收到接收方的确认（ACK） 的总时间
发送方 ────────── 数据包 ──────────→ 接收方
       ←────────── ACK回复 ──────────
       |←────────── RTT ───────────→|

公式：

RTT ≈ Propagation Delay × 2 + Processing Delay × 2 + Queuing Delay × 2

RTT 不等于 Propagation Delay × 2！实际还包含处理时延和排队时延。

时延带宽积（Delay-Bandwidth Product）

  • 时延带宽积
    :一条链路上最多能容纳多少比特正在传输中
    • 单位：bit（不是bps！）
    • 物理意义：在 sender 收到第一个 ACK 之前，链路上的数据量

公式

Delay-Bandwidth Product = Propagation Delay × Bandwidth

CRC

不用等，大的要来了

什么是CRC？

  • CRC（Cyclic Redundancy Check，循环冗余校验）
    :他的功能是用来检查，发送端传向接收段的数据是否产生了错误，如果有错误，则丢回发送端让发送端重传一个数据。
    • CRC只有检测功能，没有纠错功能

那么，要怎么计算CRC呢？ 

设
数据 D（要发送的二进制数据）
生成多项式 G（收发双方约定好的除数），长度 = r+1 bits
余数 R（FCS，帧检验序列），长度 = r bits
  • CRC的计算分为三步
    • Step1：补零

      在D后面补r个0，得到$D \times 2^{r}$

    • Step2: 模2除法（也就是XOR）

      用 $D \times 2^{r} \div G$，作模2除法，得到余数R

    • Step3: 拼接发送

      将R拼接在D后面发送，也就是$D + R$

说了那么多，那么，到底什么是模2除法呢？
我会用最直接、最真相、最不绕弯……后面忘了的方式来讲解

设 D 为 101001，G 为 1101，r = 3（因为G的长度为4）
  • Step1：补零，得到 101001000
  • Step2：模2除法（全程 XOR，不进位不退位）
            ___________
        1101)101001000
             1101
             01110
              1101
              001110
                1101
                001100
                  1101
                  0001   ← 取后r位，余数 R(也叫FCS) = 001
  • Step3：拼接，发送帧=101001001
  • 等接收方接收到信号时，接收方只干一件事，用同一个G，对发送帧再次做模2除法
    • 显然，正常情况下，余数肯定为0，这个时候就说明传输没有问题。
    • 但是，如果这个时候计算余数不为0，那么恭喜你，传输出问题了，这个时候就要丢回发送端重新传输

诶，这时候有人要问了，主播主播，如果我在传输过程中一不小心，负负得正了怎么办，即便传输错误了但是余数还是0怎么办呢？
这就要分类讨论一下了
先说结论，所有奇数个错、所有突发长度 $\leq$ r 的 burst error，CRC一定能检测出问题

  • 奇数个错，顾名思义就是我接收端接收到的结果有奇数个位置出错了，那么这个时候CRC一定能检测出问题

  • 偶数个错，CRC不一定能检测出爆错

  • burst error（突发错误）

    指连续一串bit都被传错了，比如010 $\longrightarrow$ 101,这时burst error为3

    • $burst error \leq r$ , CRC一定能检测出问题
    • $burst error = r+1$ , CRC检测出问题的概率为 $1-\frac{1}{2^{r-1}}$
    • $burst error \gt r$ , CRC检测出问题的概率为 $1-\frac{1}{2^{r}}$

关于这个证明因为篇幅太长，这里地方太小，写不下，所以可以移步到关于CRC检测是否出问题的证明

我觉得大家来看这篇文章可能都是奔着考试来的，那么说了这么多，让我们看看CRC的常见考点有哪些吧

考点 说明
r 怎么确定 r = 生成多项式 G 的最高次数 = G 的 bits 长度 - 1
G = 1101 最高次是 3，所以 r = 3，FCS = 3 bits
模2除法 就是 XOR（异或），同0异1
$G=x^{3}+x^{2}$+1 写成二进制就是 1101
FCS长度 固定 = r bits
检错能力 所有奇数个错、所有突发长度 $\leq$ r 的 burst error

海明码

如果说CRC是检错工具，那么海明码就是纠错工具

  • 什么是海明码

    海明码是在数据中插入若干校验位位，用来纠正数据出错的一个工具

  • 海明码的公式计算

    $2^{r} \geq k+r+1$

    • 其中 $k=$ 数据位的位数
    • $r=$ 校验位的位数

举个栗子，数据1011需要多少校验位？

观察得，$2^{2} \leq 4+2+1 = 7$
$2^{3} \geq 4+3+1 = 3$
所以是3位

  • 那么，海明码是怎么工作的呢？
    • 海明码将$r$位校验位放在$2^{0},2^{1},2^{2}……$的位置
    • 第$i$位校验位的值，覆盖所有位号二进制表达中第$i$位为1的个数（使总和为偶数）
    • 如果和正常的情况不一致，纠错

主播主播，第$i$位校验位的值，覆盖所有位号二进制表达中第$i$位为1的个数（使总和为偶数）是啥意思啊我怎么有点看不懂
下面我将用一个例题来说明这句话的意思

现在有发送数据1010，请问它的海明码是多少呢？

  • Step1，确认海明码的位置
    易得，k=4，r=3
    于是，三位海明码放在1，2，4的位置
    位号 1  2  3  4  5  6  7
         P1 P2 D1 P3 D2 D3 D4
               1     0  1  0
    P1,P2,P3即为校验码
  • Step2，计算校验位
    P1:覆盖位1(001)，3(011)，5(101)，7(111)->数据位为3，5，7->和为1+0+0=1（奇数）->P1=1
    P2:覆盖位2(010)，3(011)，6(110)，7(111)->数据位为3，6，7->和为1+1+0=2（偶数）->P2=0
    P3:覆盖位4(100)，5(101)，6(110)，7(111)->数据位为5，6，7->和为0+1+0=1（奇数）->P3=1
  • Step3：发送帧
    位号 1  2  3  4  5  6  7
         P1 P2 D1 P3 D2 D3 D4
         1  0  1  1  0  1  0
    P1,P2,P3即为校验码
  • Step4：假设传输过程中位5出错，那么应该怎么纠正呢？
    位号 1  2  3  4  5  6  7
         P1 P2 D1 P3 D2 D3 D4
         1  0  1  1  1  1  0
    重新计算校验位
    P1：1，3，5，7：1+1+1+0=3（应为偶数），不一致记作1
    P2：2，3，6，7：0+1+1+0=2（为偶数），一致记作0
    P3：4，5，6，7：1+1+1+0=3（应为偶数），不一致记作1

    还记得我们P1，P2，P3所在位数用二进制怎么表达吗？
    依次是001，010，100
    所以我们可以得到序列P3，P2，P1为101，转化为二进制为5，标志着第五位出错了

以上就是整个海明码的流程了

  • CSMA/CD是用来干啥的

    当多台电脑共享同一根以太网线缆的时候，如果同时发送数据，就有可能会发生碰撞，CSMA/CD就是用来解决这个问题的协议

二进制指数退避机制

提问，检测到碰撞之后立马重传吗？

答案是否定的，因为如果立马重传可能又会重新发生碰撞
那么要怎么解决这个问题呢？答：设置一个随机等待时间

公式：

$退避时间 = 基本退避时间 \times 随机数r$
符号表示为 $退避时间 = 2\tau \times r$

  • $\tau$ = 端到端传播时延
  • 基本退避时间 = $2\tau$（争用期/碰撞窗口）
  • $r=rand(0,2^{k}-1)$（当k=1时，r取值只有0或1）
  • $k=min(重传次数，10)$
  • 重传 $\geq 16 \rightarrow$ 丢弃，重传
  • 争用期（碰撞窗口）（Contention Period）
    :在这段时间内没检测到碰撞 $\rightarrow$ 这次发送必定成功
  • 最短帧长（Minimum Frame Length）
    :帧不能太短，否则碰撞信号回来时帧已经发完了，检测不到碰撞
    • $最短帧长 = 争用期 \times 数据传输速率$

  • 以太网帧结构分为

    • 8 bytes Preamble（前导码）

      同步时钟，接收方用它来同步发送方的时间

    • 6 bytes Dest MAC（目的MAC）

      接收方

    • 6 bytes Src MAC（源MAC）

      发送方

    • 2 bytes Type（类型）

      上层协议

    • 46~1500 bytes Payload（数据）

      数据（不够46补padding）

    • 4 bytes FCS（帧检验序列）

      CRC校验全文

  • 两个限制

    • 最短帧长 = 64 bytes（从Dest MAC算到FCS）

      数据只有46 bytes 的原因 $64-6-6-2-4=46$
      为什么最短64？为了CSMA/CD能检测到碰撞（争用期 $\times$ 速率）

    • 最大帧长 = 1518 bytes（数据最多1500）

IEEE 802.11（无线局域网/Wi-Fi）

  • 使用CSMA/CA协议
  • 无法检测冲突，只能等ACK超时
  • 存在隐藏站问题

    什么是隐藏站问题？

     A ──── B ──── C
        能通信     能通信
     A,C 互相听不到

当A，C同时发信号给B时，因为A，C互相听不到，所以会以为信道空闲，然后碰撞

解决方法：RTS/CTS（Request to Send / Clear to Send）

当A要发信号时，B广播一个信号，表示A要发信号了，让别的先别发，等A发完再发

知道概念即可，已被以太网取代

  • 工作原理
    • 将设备连成环形，将一个特殊的token在环上单向传播，只有拿到token的设备才能发数据
    • 优点：无碰撞，公平性好
    • 缺点：一单某个设备出问题那就寄了，环直接断开

MAC地址

  • 什么是MAC地址

    MAC地址，也叫物理地址（本质上是网络设备的物理地址），是每块网卡硬件的唯一编号
    MAC地址在数据链路层这一层起作用，只要没有跨网段，只要还在局域网转发，考的就是MAC地址（不看IP）

  • MAC地址的核心三要点

    • 全球唯一性，每块网卡都不同，所以MAC地址是唯一的
    • 固化性，一旦出场写入，那么就固定在硬件里不再更改
    • 局域网范围，MAC地址在不经过路由的情况下，无法跨网络使用

  • MAC地址的地址格式

    MAC地址长度为6bytes=48bits，通常以16进制XX-XX—XX-XX-XX-XX的形式表示
    前三字节是厂商识别码（OUI），是IEEE分配给厂商的唯一代码
    后三字节是网卡序列号，是厂商自己给网卡分配的编号

  • 交换机MAC表

    • 当一个数据帧到达交换机时，交换表会检查自己的MAC表
    • 如果在MAC内找到了对应得MAC地址，那么就从对应端口转发
    • 如果没有就广播给其他端口

一个栗子
假设我现在有终端B（发送方）要经过路由到终端C（接收方）
他们之间的关系为B(A1-DA-95-5F-CA-61)$\rightarrow$(BF-9D-8A-F3-C5-AE，点一)路由(96-49-67-CA-75-43，点二)$\rightarrow$C(41-E6-32-2F-AE-B0)
那么我们就可以得到

  • 在点1处
    • source mac address：A1-DA-95-5F-CA-61（因为起点是B，这里就要填B的MAC）
    • destination mac address：BF-9D-8A-F3-C5-AE（路由器入口的MAC地址）
  • 在点2处
    • source mac address：96-49-67-CA-75-43（路由器出口的MAC地址）
    • destination mac address：41-E6-32-2F-AE-B0（终点C的MAC地址）

MAC地址表（转发表）的构建过程（自学习）

交换机的MAC地址表是自学习的，不需要手动配置：

初始状态：MAC表为空

Step 1: A(00-1A)从端口1发数据给C
         → 学到：00-1A → 端口1
         → 不知道C在哪，从2,3,4广播

Step 2: B(00-2B)从端口3发数据给A
         → 学到：00-2B → 端口3
         → 已知A在端口1，直接从端口1转发

Step 3: C(00-3C)从端口4发数据
         → 学到：00-3C → 端口4

→ 经过自学习，MAC表逐渐构建完整

MAC地址表的结构：

MAC地址 对应端口 老化时间
00-1A-2B-3C-4D-5E 端口1 300s
00-2B-3C-4D-5E-6F 端口3 300s
  • 老化机制： 一段时间没收到某MAC的帧就删掉记录，防止过时
  • 动态更新： 每次收到帧都刷新对应记录的时间

一句话总结就是，MAC地址只在同个局域网内生效，并且发送方和接收方的MAC地址只有起点和终点决定，当经过路由转换后，新的起点要更新成路由的MAC地址，这是交换价MAC表内的MAC

PPP协议（Point-to-Point Protocol）

用在哪儿？ 两台设备之间点对点连接，比如：

  • 家庭宽带拨号（PPPoE）

  • 路由器之间的专线连接

  • PPP的三大部分

    • HDLC-like Framing：组帧方式，类似HDLC的位定界
    • LCP（Link Control Protocol）：建立、配置、测试数据链路连接
    • NCP（Network Control Protocol）：协商网络层（如IP）的参数

  • PPP的工作过程（三步走）

    1. LCP配置 → 建立连接、协商参数（MTU、认证方式等）
    2. 认证（可选） → PAP（明文密码）/ CHAP（加密握手）
    3. NCP配置 → 分配IP地址等网络层参数，之后开始传输

  • PPP帧结构

    • 1 bytes Flag（标志）

      01111110，标记帧开始/结束

    • 1 bytes Addr（地址）

      11111111（广播地址，点对点没意义）

    • 1 bytes Ctrl（控制）

      00000011（无编号帧，表明不有序传输）

    • 2 bytes Protocol（协议类型）

      标明上层协议，比如0021=IP、8021=IPCP

    • ≤1500 bytes Payload（数据）

      数据部分

    • 2/4 bytes FCS（帧检验序列）

      CRC校验

注：PPP常用字节填充（Byte Stuffing），而不是bit stuffing

HDLC协议（High-level Data Link Control）

地位： PPP的前身，现在被PPP基本取代

  • HDLC的三种帧类型

    • I-Frame（信息帧）：传输上层数据，带序号
    • S-Frame（监控帧）：ACK、NAK、流量控制
    • U-Frame（无编号帧）：建立/释放连接等

  • HDLC的三种工作模式

    • NRM（正常响应模式）：从站只有被主站轮询才能发
    • ABM（异步平衡模式）：双方平等，随时可发（最常用）
    • ARM（异步响应模式）：从站不等轮询就能发

ABM是最常用的模式，PPP用的就是类似ABM的思路

  • PPP vs HDLC 对比
PPP HDLC
本质 HDLC的简化版 功能全但复杂
组帧 字节填充（Byte Stuffing） 比特填充（Bit Stuffing）
认证 ✅ 支持（PAP/CHAP） ❌ 不支持
多协议支持 ✅ 强（Protocol字段） 相对弱
现状 广泛使用 ⭐ 基本被取代

滑窗机制与三种停等协议

发一个等一个ACK，信道利用率太低
一次发多个，一口气等ACK，效率高很多

这个”一次最多能发多少个还没被ACK的packets”就是窗口大小（Window Size）

三种ARQ协议总览

协议 发送窗口 接收窗口 重传策略
停等协议（Stop-and-Wait） 1 1 发一个等一个
后退N帧（Go-Back-N / GBN） > 1 1 从出错起全部重传
选择重传（Selective Repeat / SR） > 1 > 1 只重传出错的

Stop-and-Wait ARQ（停等协议）

特点： 发一个，等ACK，再发下一个

Sender:  [发1] → 等ACK → [发2] → 等ACK → [发3]
Receiver:[    ACK1→]       [    ACK2→]
  • 发送窗口 = 接收窗口 = 1
  • 优点： 实现最简单
  • 缺点： 信道利用率最低

Go-Back-N ARQ（后退N帧协议）

特点： 连续发多个packets，一旦出错，把错的以及之后所有的packets全部重传

Sender:   [1][2][3][4][5]       ← 连续发
Receiver: [1][2][X][4][5]       ← packet 3 丢了/出错
Sender:      重传 [3][4][5]     ← 从3开始全部重传！
  • 发送窗口大小 = $2^m - 1$（最大，m为序号位数）
  • 接收窗口大小 = 1（只收顺序到达的，乱序直接丢弃）
  • 缺点： 一个出错，后面全重传，浪费带宽

Selective Repeat ARQ（选择重传协议）

特点： 连续发送，只重传出错的packet，接收方有buffer缓存乱序到达的

Sender:   [1][2][3][4][5]       ← 连续发
Receiver: [1][2][X][3][4]       ← packet 3 丢了，缓存4和5
Sender:      只重传 [3]         ← 只补3！
  • 发送窗口 = 接收窗口 = $2^{m-1}$
  • 优点： 信道利用率最高，不浪费带宽
  • 缺点： 实现最复杂，接收方需要buffer

网桥（Bridge）与交换机（Switch）

网桥（Bridge）的概念

网桥是一个Data Link Layer设备，连接两个局域网段，基于MAC地址做转发

  • 功能
    • 识别MAC地址，根据MAC地址做帧转发
    • 分割冲突域（Collision Domain），但不分割广播域
  • 工作方式
    • 收到frame后查MAC表（转发表）
    • 如果目的MAC在同一个网段就不过去（过滤）
    • 如果目的MAC在另一个网段就转发
    • 如果不知道就广播

Hub vs Bridge vs Switch

  • Hub是物理层设备，只转发bit，不分割冲突域
  • Bridge是数据链路层设备，能识别MAC，分割冲突域
  • Switch是多端口的Bridge，每个端口是一个独立的冲突域

交换机（Switch）的工作原理

Switch = 多端口高性能的Bridge，是现代以太网的核心设备

交换机的帧转发过程

1. Switch从某个端口收到一个frame
2. 提取frame中的源MAC地址和目的MAC地址
3. 查MAC地址表（转发表）
    ├── 找到了目的MAC对应的端口
    │   └── 从该端口转发（如果和接收端口相同则丢弃/过滤）
    └── 没找到目的MAC对应的端口
        └── 从除接收口以外的所有端口广播（泛洪）
4. 更新MAC地址表（把源MAC地址和接收端口对应起来）

交换机三种转发方式

方式 特点
存储转发（Store-and-Forward） 完整接收整个frame后再转发，可以错误检测，延迟大
直通转发（Cut-Through） 只读出目的MAC就立即转发，延迟小，不能纠错
无碎片转发（Fragment-Free） 读到前64 bytes就转发，避免碎片帧，折中方案

最短路例题

距离-向量路由（RIP）

本质是Bellman-Ford算法，每个节点只知道邻居的信息，反复交换”距离表”直到收敛

  • Bellman-Ford算法的流程为，初始时，每个节点只知道自己和直连邻居的距离，到其他节点的距离设为 $\infty$
  • 然后，把起点加入队列，不断从队列取出节点来松弛它的邻居
  • 显然，点u到点v的最短路径 = $d_{u,v} = min (d_{u,v},d_{u,x}+d_{x,v})$
  • 循环上面的操作，直到所有点都加入队列中

链路状态路由（OSPF）

本质是Dijkstra算法，每个节点知道全图拓扑，以自己为起点一步步找最短路径

  • Dijkstra算法的流程为，初始时，起点到自己的距离为0，到其他节点的距离设为 $\infty$
  • 创建一个集合S，存放已确认最短路径的节点。每次从未确认的节点中，选出距离起点最小的节点加入S
  • 选出一个节点后，用它去松弛它的所有邻居：若 $d_{u,v} > d_{u,x} + d_{x,v}$，则更新距离并记录前驱节点
  • 循环上面的操作，直到所有节点都加入S

和Bellman-Ford不一样的地方：Dijkstra里一旦节点加入了S，它的最短距离就不会再变了（因为每次都是选最小的）

  2. 连续的全0组可用::代替一次：2001:0db8::8a2e:0370:7334

路由协议（掌握）

自治系统（AS，Autonomous System）

互联网被划分为一个个自治系统，每个AS内部运行相同的路由协议

域内路由（IGP）vs 域间路由（EGP）

IGP（域内路由协议） EGP（域间路由协议）
范围 AS内部 AS之间
代表协议 RIP、OSPF BGP
目标 找最短路径 遵循策略（政治、经济等）

BGP（Border Gateway Protocol）

  • 路径-向量路由协议，不是距离-向量也不是链路状态
  • AS之间交换可达性信息（路径向量），而不是距离
  • 基于策略路由：可以设置路由过滤、偏好等策略
  • 使用 TCP端口179 建立连接

IP组播（Multicast，理解）

什么叫组播？

类型 发送方式 特点
单播（Unicast） 一对一 发N份给N个接收者
组播（Multicast） 一对多 只发一份，沿途复制
广播（Broadcast） 一对全体 发给所有设备

组播地址（D类）： 224.0.0.0 ~ 239.255.255.255

组播的优点：

节省带宽——即使有1000个接收者，源端也只发一份数据

移动IP（了解）

解决什么问题？

你的设备从一个网络移动到另一个网络时，IP地址变了，原本的连接就断了

工作原理：

  • 每个移动设备有一个**归属地址（Home Address）**固定不变
  • 到外地网络时，获取一个转交地址（Care-of Address）
  • 归属代理（Home Agent） 把发往归属地址的数据隧道转发到转交地址

Part5：传输层

既是重点又是难点，需了解端口号的作用，TCP与UDP数据包的结构。重点是TCP协议的流量控制与拥塞控制机制，窗口大小的变化过程，序列号大小的计算。

传输层提供的服务（掌握）

传输层的功能

  • 提供端到端（Process-to-Process） 的通信，不同于网络层的”主机到主机”
  • 对收到的数据进行复用（Multiplexing） 和分用（Demultiplexing）
  • 提供可靠或不可靠的数据传输

传输层寻址与端口（Port）

端口号的作用： 标识主机上的特定进程/应用

端口类型 范围 例子
熟知端口（Well-Known） 0~1023 HTTP=80，HTTPS=443，FTP=21，SSH=22
注册端口（Registered） 1024~49151 数据库、应用服务
动态/私有端口（Dynamic） 49152~65535 客户端临时使用

套接字（Socket） = IP地址 + 端口号

无连接服务 vs 面向连接的服务

UDP（无连接） TCP（面向连接）
是否需要建立连接 ❌ 不需要 ✅ 需要（三次握手）
可靠性 ❌ 不可靠 ✅ 可靠传输
有序性 ❌ 不保证 ✅ 保证有序
流量控制 ❌ 无 ✅ 有
拥塞控制 ❌ 无 ✅ 有
开销 小 大
适用场景 实时应用（视频、DNS） 文件传输、网页浏览

流量控制与可靠传输机制

这部分在数据链路层已经讲过，但传输层（TCP）的语境下有不同

传输层的流量控制 vs 数据链路层的流量控制：

  • 数据链路层：控制的是相邻节点之间的流量
  • 传输层：控制的是发送端和接收端之间的流量（端到端）

滑动窗口机制：

  • 发送方维护一个发送窗口，一次能发多个segment
  • 接收方通过通告窗口（Advertised Window） 告诉发送方”我还能收多少”
  • 发送窗口取 min(拥塞窗口, 通告窗口)

三种ARQ协议（已在数据链路层详述）：

  • 停等协议：发一个等一个
  • 后退N帧（GBN）：出错后全部重传
  • 选择重传（SR）：只重传出错的

UDP的特点：

  • 无连接：发送前不需要建立连接
  • 不可靠：不保证数据到达，没有重传机制
  • 低开销：头部只有8 bytes
  • 支持广播和组播（TCP不支持）
  • 常见应用：DNS（53）、DHCP（67/68）、视频流、VoIP

TCP协议（熟练掌握）

TCP报文段结构

标志位（Flags）：

  • URG：紧急指针有效
  • ACK：确认号有效（除了SYN包，其他包ACK通常=1）
  • PSH：接收方应尽快把数据交给应用层
  • RST：复位连接
  • SYN：发起连接（三次握手的第1、2步）
  • FIN：释放连接
字段 长度 含义

确认号（ACK） 32 bits 期望收到的下一个字节的序号
数据偏移 4 bits TCP头部长度，单位4 bytes
窗口大小 16 bits 接收方还能接收多少数据（通告窗口）

为什么要三次握手？

  • 防止已失效的连接请求突然又传到服务器，导致错误建立连接
  • 双方都要确认对方的收发能力正常

三次握手的状态变化：

  • 客户端发SYN → SYN_SENT
  • 服务器收到SYN → SYN_RCVD
  • 客户端收到SYN+ACK → ESTABLISHED
  • 服务器收到ACK → ESTABLISHED

TCP四次挥手（连接释放）

为什么需要四次挥手？

TCP是全双工的，两边都要单独关闭

  • 客户端说”我不发了”（FIN）
  • 服务器说”收到了”（ACK）
  • 服务器说”我也不发了”（FIN）
  • 客户端说”收到了”（ACK）

为什么要TIME_WAIT（2MSL）？

确保服务器收到了最后的ACK，如果没收到可以重传

TCP可靠传输

TCP通过以下机制保证可靠：

  • 序号和确认号：每个字节都有序号，接收方通过确认号告诉发送方收到了哪些数据
  • 超时重传（RTO）：发出去后如果超时没收到ACK就重传
  • 快速重传：收到3个重复ACK就立即重传，不等超时

TCP流量控制与拥塞控制

流量控制（Flow Control）：

解决接收方收不过来的问题

  • 接收方在ACK中带回窗口大小（rwnd，Advertised Window）
  • 发送方的发送窗口不能超过 rwnd
  • 如果 rwnd = 0，发送方停止发送，但定期发送零窗口探测包

拥塞控制（Congestion Control）：

解决网络中间设备（路由器）处理不过来的问题

拥塞控制的四种算法：

① 慢启动（Slow Start）

cwnd增长过程：1 → 2 → 4 → 8 → 16 → …

② 拥塞避免（Congestion Avoidance）

cwnd增长过程：… → 16 → 17 → 18 → …（线性增长）

③ 快重传（Fast Retransmit）
④ 快恢复（Fast Recovery）

如果发生超时（Timeout）：

超时 vs 快重传的区别

  • 超时：更严重，表示网络可能已经拥堵到连ACK都到不了 → cwnd重置为1
  • 3个重复ACK：较轻，ACK还能回来只是丢了几个包 → cwnd减半

拥塞窗口变化过程图

必记计算公式：

超时时：ssthresh = cwnd/2，cwnd = 1
快重传+快恢复：ssthresh = cwnd/2，cwnd = ssthresh

网络应用模型（了解）

C/S模型（Client/Server，客户/服务器模型）

  • 特点： 客户端主动请求，服务器被动响应
  • 服务器一直运行，等待客户端连接
  • 客户端之间不直接通信
  • 缺点： 服务器压力大，扩展性有限

P2P模型（Peer-to-Peer，对等网络模型）

  • 特点： 每个节点既是客户端也是服务器
  • 没有中心服务器，资源分布在各个节点上
  • 优点： 扩展性好，不依赖中心服务器
  • 例子： BitTorrent、迅雷

两种模型对比：

C/S模型 P2P模型
角色 固定（服务器和客户端） 对等（既是客户端也是服务器）
服务器压力 大 无中心服务器
扩展性 差 好
管理 集中管理 分布式管理
典型应用 Web（HTTP）、FTP、Email 文件分享、区块链
